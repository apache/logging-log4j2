= Modernization performance validation

The Log4j modernization initiative adds TrustGate input validation and refactors core modules.
Release validation compares JMH benchmark results against committed baseline fixtures and fails when
throughput or latency regresses beyond the 2% NFR threshold.

== Benchmark coverage

[cols="2,4", options="header"]
|===
|Suite |Purpose

|`TrustGateValidationBenchmark`
|Microbenchmarks for `InputSanitizer.validate()` and validation rules on common and attack-path inputs

|`AsyncLoggersBenchmark`
|Asynchronous logger throughput with parameterized messages

|`AsyncAppenderLog4j2Benchmark`
|Async appender throughput via the LMAX Disruptor ring buffer

|`JsonTemplateLayoutBenchmark`
|JSON template layout encoding throughput (see xref:manual/json-template-layout.adoc#performance[])
|===

TrustGate common-path latency target is below 100 ns per invocation; async throughput must remain within
2% of the stored baseline on the reference CI hardware profile.

== Baseline comparison workflow

Build the perf-test uber JAR and run benchmarks with JSON output:

[source,bash]
----
mvn -pl log4j-perf-test -am package -DskipTests
JAR=log4j-perf-test/target/log4j-perf-test-*-uber.jar

java -jar $JAR TrustGateValidationBenchmark -wi 5 -i 10 -f 1 \
  -rf json -rff target/trustgate-validation-current.json
----

Compare current results against committed fixtures:

[source,bash]
----
java -cp $JAR org.apache.logging.log4j.perf.jmh.BenchmarkBaselineComparator \
  log4j-perf-test/src/test/resources/baseline/trustgate-validation-baseline.json \
  target/trustgate-validation-current.json \
  target/trustgate-validation-comparison.adoc
----

The comparator exits with a non-zero status when any benchmark exceeds the 2% degradation threshold.
An AsciiDoc comparison table can also be generated via
`JsonTemplateLayoutBenchmarkReport` in three-argument baseline comparison mode.
